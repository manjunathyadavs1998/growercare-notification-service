# notification-service: project guide for Claude

GrowerCare message dispatch (ADR-017: its own repository). Other services call `POST /internal/messages` (allow-listed service clients only); notification-service renders a template per language and hands it to the channel's provider (SMS, WhatsApp, email). Phase 1 has only the **mailbox** provider: messages are stored in a local dev mailbox instead of being sent (PRD D2). Case and comment notifications from events come with SPEC-NOT-02.

## Conventions
1. **No end users:** every user token is 401; only clients in `GC_INTERNAL_CLIENTS` may send.
2. **Secrets in messages:** a body (it may hold a one-time code) or a full recipient never appears in logs, the delivery log, responses or `toString()`. Only the local dev mailbox holds bodies.
3. **The dev mailbox is local only:** `GC_DEV_MAILBOX=true` registers `/dev/mailbox` (no token) and is refused together with any real provider.
4. **Templates:** one file per language; no fallback language. A missing text is a defect (422).
5. **No ORM:** named SQL via `JdbcClient` (ADR-013), `sql/postgres/notify.sql`.
6. **Configuration only from environment variables** (SPEC-PLAT-06), documented in `.env.example`; `ConfigurationHygieneTest` guards it.
7. **Spec-driven development:** spec → parameterized test rows named after spec example IDs → code → green.
8. **Reporting:** run `mvn -B verify` before claiming success.
9. **Git workflow:** never commit to `main`; branch `<type>/<name>`; PR body with `Spec: docs/specs/...`; squash-merge when CI, policy and Claude review are green.
